Surogate is a platform for building, deploying, and improving autonomous AI agents. An
agent is a model plus a persona, the skills it follows, the knowledge bases it searches
while answering, the tools it may call, and the guardrails it operates under. Agents do
real work: they browse the web and hand control back to a person for login or MFA, reach
your internal systems through MCP servers using credentials held in a vault the agent
never sees, delegate to sub-agents on long-running missions, and remember context across
conversations.

Every message, tool call, and governance decision is written to an append-only event log,
so every session is recorded and replayable. Flag the turns that went well or badly, build
evaluation sets out of real failures, and — when configuration changes stop being enough —
fine-tune an expert model on the data you collected and serve it back to the agent.
Configuration changes apply to new sessions immediately while in-flight sessions finish on
the version they started on, and any version rolls back.

## The improvement loop

You [build](/develop/loop/build/) an agent from configuration rather than code;
[observe](/develop/loop/observe/) what it actually did in the
[session log](/develop/features/sessions/) and flag the good and bad turns;
[train](/develop/loop/train/) either the cheap way — edit a skill, a persona, a knowledge
base — or the expensive way, by fine-tuning an expert on the sessions you flagged; then
[redeploy](/develop/loop/redeploy/). [The builder loop](/develop/loop/overview/) walks all
four phases and gives the end-to-end time for each kind of change; the same cycle without
the configuration detail is [Improve your agent](/work/workflow/improve-agent/).

## Capabilities

Each row links to the page that covers it. Feature pages live in Develop mode; the
day-to-day usage pages live in Work mode.

| Capability | What it does |
| --- | --- |
| [Agents](/develop/features/agents/) | A model, persona, skills, knowledge, tools, and guardrails, deployed as a service your users can talk to. |
| Channels | The same agent on [web chat](/work/channels/web/), [Slack](/work/channels/slack/), [Telegram](/work/channels/telegram/), an [embeddable widget](/work/channels/website-widget/), or the API — sharing one [memory](/develop/features/memory/). |
| [Skills and experts](/develop/features/skills-and-experts/) | Reusable procedures an agent follows, plus fine-tuned specialists it consults for hard, repeated problems. [Skill optimization](/develop/features/skill-optimization/) proposes edited skills, scores them, and keeps the best. |
| [Knowledge bases](/develop/features/knowledge-bases/) | Document collections searched during the conversation, so answers come from your material with sources attached. |
| [Tools and credentials](/develop/features/mcp-and-vault/) | MCP servers connect an agent to your systems and to third-party APIs; secrets stay in a vault and are never exposed to the agent's runtime. |
| [Browser control](/develop/features/browser/) | Agents drive a real Chromium browser and hand control back to a person for login, MFA, or anything needing judgement. |
| Long-running work | [Missions](/work/tools/missions/) graded against success criteria, [sub-agents](/work/tools/sub-agents/) for delegated parts, an [inbox](/work/tools/inbox/) for approvals, and [arenas](/develop/features/experts-arenas/) — in preview — for supervised multi-agent runs. |
| [Sessions](/develop/features/sessions/) | Every message, tool call, and result recorded and replayable. [Event types](/develop/reference/event-types/) explains what the log contains; [reviewing sessions](/work/workflow/review-sessions/) is the day-to-day flagging workflow. |
| [Evaluations](/develop/features/evaluations/) | Score an agent or a model against 40 built-in benchmarks, or a custom benchmark built from your own failed sessions, then A/B two candidates before promoting either. |
| [Models](/develop/features/models/) | Catalog, serving endpoints with quantization and autoscaling, and versioned rollback — or [bring your own LLM](/develop/features/byo-llm/) per agent. Runs execute on the providers you attach under [Compute](/develop/features/compute/). |
| [Training](/develop/features/training/) | Supervised fine-tuning, LoRA and QLoRA adapters, mixture-of-experts and long-context runs distributed across several GPUs and nodes, and reinforcement learning against verifiable rewards or an LLM judge. |
| [Datasets](/develop/features/datasets/) | Training and evaluation sets built from real sessions, uploads, or synthetic generation — profiled, scanned for PII, and versioned in the [Data Hub](/develop/features/hub/). |
| Security and governance | Guardrails are locked when a session starts and cannot be weakened mid-task, sandboxed code is network-restricted, integrations are scanned for tampering, and every action lands in the event log. See [how the runtime behaves](/develop/reference/runtime-architecture/). |
