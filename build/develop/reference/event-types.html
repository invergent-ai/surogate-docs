Event types

The Sessions UI's EVENTS tab and the GET /v1/sessions/{id}/events API both return a stream of typed events. This page lists what you'll see and what each event tells you.

Conversation events​

TypeWhenWhat's useful
user.messageA user sent inputcontent, source (web / slack / api / scheduled / …)
assistant.finalThe agent produced a final user-visible responsecontent
llm.request / llm.responseA single LLM call (the agent may make many per turn)model, tokens_in, tokens_out
clarify.responseThe user answered an ask_user_question prompt (the event type keeps the legacy clarify name)tool_call_id, responses

Tool execution​

TypePayload
tool.callname, args, tool_call_id
tool.resulttool_call_id, content, duration_seconds, status
tool.errortool_call_id, error

For most debugging, the EVENTS tab's TOOLS sub-view filters these for you. Programmatically, GET /v1/sessions/{id}/events?type=tool.call is the API equivalent.

Sub-agent / task events​

When a session spawns child sessions via spawn_worker / delegate_task / spawn_task, the children's outcomes flow back as events in the parent's log.

TypeWhen
worker.spawnedA child session was created
worker.completeChild finished normally; payload includes the truncated result and optional metadata
worker.failedChild errored or hit its iteration budget
delegation.start / delegation.complete / delegation.failed / delegation.staleDetailed observability for delegate_task calls
task.blockedA task self-paused via task_block
task.failedA task exhausted its retry budget

Governance​

TypeWhen
policy.deniedA tool call was blocked by the governance gate. Payload: tool, reason, timestamp
policy.allowedA tool call passed the gate — emitted only when the deployment enables governance.log_allowed (off by default; doubles event volume). Payload: tool, check: "governance_gate", timestamp
disclosure.presentedA messaging channel (Slack / Telegram / WhatsApp) posted the AI disclosure as the first message of a new conversation. Payload: level, channel, delivery: "channel_message"
disclosure.confirmedA web user accepted the disclosure banner. Payload: level, source: "web_banner"

The two disclosure.* events are the Art. 50 compliance evidence trail — see Governance & AI disclosure.

Saga (multi-step rollback)​

When the agent's CONFIG has Saga enabled:

TypeWhen
saga.startSaga activated at session start
saga.step_begin / saga.step_committed / saga.step_failedPer-step tracking
saga.compensateA rollback fired
saga.completeSaga finished
saga.escalatedA compensation step itself failed — operator must intervene

Experts​

TypeWhen
expert.delegationBase LLM called consult_expert
expert.resultThe expert returned
expert.overrideBase LLM rejected the expert's output (counts against expert success rate)
expert.endorseBase LLM used the expert's output verbatim

Outcomes (/goal)​

TypeWhen
outcome.definedA goal was set on the session
span.outcome_evaluation_endThe evaluator returned a verdict (satisfied, needs_revision, blocked, failed)
outcome.continuationA continuation message was queued

Inbox​

The agent raised something to the user:

TypeWhat it surfaces
inbox.input_requiredAn ask_user_question prompt
inbox.action_requiredAn external action needed (browser login, MFA, etc.)
inbox.task_completeAn informational completion
inbox.governance_gateReserved for user-overridable policy denials — not currently produced (no policy decision is marked overridable today)
inbox.progress_checkinA long-running-session status update

Lifecycle​

TypeWhen
session.created / session.completed / session.failed / session.archivedSession-level transitions
session.resetThe idle-session-reset background job tore down the sandbox (memory was flushed to MEMORY.md/USER.md first)
harness.crash / harness.recoveredRare — a runtime crash and the subsequent automatic recovery
context.compactThe session's context window was compressed automatically
artifact.createdA create_artifact call produced an inline chat artifact

Querying via the API​

# All events for a session
GET /v1/sessions/{id}/events

# Filter by type
GET /v1/sessions/{id}/events?type=policy.denied

# Stream live (SSE)
GET /v1/sessions/{id}/events?after=<last_id>

See the API reference for full schemas. For Slack and Telegram channel sessions, the same events stream is available — channel adapters just translate the user-visible portion into the channel's native format.

Stability​

Event type names and their documented payload keys are a stable contract. Adding new keys is safe; renaming or removing requires a deprecation cycle. If you're querying programmatically, prefer reading specific keys (event.data.tool) over depending on the full payload shape.
