# Studio dashboard

The Studio dashboard is the first page you see when you switch to **Develop** mode. It's a single screen designed to answer four questions at a glance: how many agents are alive, how many models are serving, what's training, and what conversations just happened.

This page is the reference for each panel on the dashboard.

## The four KPI tiles

A row of four tiles across the top:

| Tile | What it counts |
|---|---|
| **Active Agents** | Agents currently in **Running** status. Excludes Deploying, Stopped, and Error. |
| **Deployed Agents** | Agents that have ever reached Running — the install's all-time productive count. Useful for "how much have we shipped". |
| **Serving Models** | Models in **Serving** status. Excludes Stopped, Deploying, and Error. Each one costs compute for as long as it's listed here. |
| **Training Jobs** | Workloads of kind `sft` or `grpo` currently in **Running** or **Queued**. Drops to zero between training runs. |

The tiles are clickable; each one drills into the filtered list (Agents → Running, Models → Serving, etc.).

## Quick Actions row

Below the KPIs, a row of six shortcut buttons:

- **Deploy Agent** — opens the same dialog as Build → Agents → Deploy Agent.
- **Serve Model** — opens the model source picker.
- **New Skill** — opens the Skill Builder.
- **Start Training** — opens the New Training Run wizard.
- **New KB** — opens the New Knowledge Base dialog.
- **New Dataset** — opens the source picker for a new dataset.

The row is designed for builders mid-flow. You're on the dashboard, you want to start the next thing, you click; you don't have to navigate the sidebar.

## Recent Conversations panel

A live list of the most recent sessions across every agent you have access to.

Three filter pills along the top:

- **All** — every session.
- **Flagged** — only sessions with a 👍 or 👎 attached.
- **Negative** — only sessions with a 👎 (or sessions an operator marked as bad in some other way).

Each row shows:

- The agent's name.
- The last user message (truncated).
- A relative timestamp.
- The flag state.

Click a row to open the session detail. The pattern most teams use: every morning, switch the filter to **Negative**, read the previous day's bad sessions, decide what to flag for the next training set.

## Agent metrics table

Below Recent Conversations, a table summarising every Running agent with operational metrics.

Columns:

| Column | Meaning |
|---|---|
| **AGENT** | Display name of the agent. Click to open the agent's detail page. |
| **VERSION** | The deployed version tag — increments with each redeploy. |
| **STATUS** | Running, Deploying, Stopped, or Error. |
| **REPLICAS** | How many serving replicas of the agent's container are live. |
| **CPU** | Average CPU utilisation across replicas. |
| **MEM** | Average memory utilisation across replicas. |
| **RPS** | Requests per second the agent is currently handling. |
| **P99** | 99th-percentile response latency in milliseconds. |
| **MODEL** | The model the agent is currently configured to call. Click to open the model's detail. |

The table refreshes every few seconds; the metrics are live, not historical.

Use it to spot:

- **An agent in Deploying that should have flipped Running by now.** Open it, find the related workload, read the logs.
- **A spike in RPS** that wasn't expected.
- **A P99 climbing past your SLO.** Either the model is overloaded (scale up replicas, swap to a bigger GPU) or a specific skill is slow (open a recent session and look at the trace).
- **CPU / MEM pegged at 100%.** The agent's container is undersized. Restart with more headroom; the platform doesn't autoscale resources on its own.

## When the dashboard is the right place to start

Three daily rituals it serves well:

- **Morning health check.** KPI tiles + agent metrics + the **Negative** filter on Recent Conversations. Five minutes; you know what's healthy and what flagged overnight.
- **Mid-flow shortcuts.** You're switching from training to building; Quick Actions saves the navigation.
- **Stand-up update.** The four KPI numbers are the right shape for a status report.

It's not the right place for:

- **Debugging a specific session.** Go to [Sessions](../features/sessions.mdx).
- **Watching a training run.** Go to [Training Runs](../features/training.mdx) or the [Workload Queue](../features/compute.mdx).
- **Reviewing benchmarks.** Go to [Evaluations](../features/evaluations.mdx).

## When something fails

- **KPI tiles show zero but you know there are agents.** Refresh; the tiles are cached briefly. If still zero, your account doesn't have read access to the projects those agents live in.
- **An agent shows in the metrics table at status Error.** Open the agent's detail. Either the model went down (most common) or a required skill failed to init. Fix upstream, redeploy.
- **Recent Conversations panel is empty.** Either no traffic, or the filter is set too narrow. Switch to **All** to see everything.
- **Dashboard slow to load.** Usually the install has accumulated a lot of historical sessions that the *Recent* query is reading through. The query is bounded but can degrade with very large session tables; report it to the platform team if it persists.
